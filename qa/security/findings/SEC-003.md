## Summary

Reproduced at the API and in the browser. Server and client do not refuse the same addresses
(the validation-parity class of SEC-001 / BUG-014). `URL_EXTERNAL` in `layout.py` is compiled with
`re.IGNORECASE` on a `str` pattern, so Python's Unicode case folding matches `ſ` (U+017F LATIN SMALL
LETTER LONG S) to `s`. As a result, `httpſ://example.invalid` and `HTTPſ://example.invalid` are accepted.
The JS regex (`/i`, without `u`) does not fold non-ASCII to ASCII, so `validUrl` refuses the same string.

No script execution or origin escape: the browser does not parse `httpſ:` as a scheme, so the href
resolves as a same-origin relative path (`/home/http%C5%BF://example.invalid`), and `isExternal` treats
it as internal. Impact is integrity: a stored link that the editor considers invalid. `toLayout`
(`layout.js` `valid()` -> `cleanLink` -> null) **silently drops it** the next time anyone saves from the
editor, and an admin default carrying it would lose it the same way.

## Steps to reproduce

Websocket as `qa_user` (non-admin, own layout):
1. `easy_sidebar_pro/save` with `links: {a: {name: "x", icon: null, url: "http\u017f://evil.example", new_tab: false}}`,
   `order: ["l:a", "history"]` -> `{"success": true}`.
2. Control: `javascript:`, `data:`, `vbscript:`, `//evil`, `/\evil`, tab/newline/NUL/U+202E/U+200B variants,
   `https:evil`, `https:///evil` are all refused (`invalid_format`).
3. Same string through `www/layout.js`: `validUrl("http\u017f://evil.example")` -> `false`;
   `normalizeUrl(...)` -> `"/httpſ://evil.example"` (turned into an internal path).
4. Admin `default/set` with the same link, then `qa_user` in the browser: row
   `#sidebar-panel-esp-link-sfs` has `href="httpſ://example.invalid"`; `a.href` resolves to
   `http://127.0.0.1:8174/home/http%C5%BF://example.invalid`; a click lands on that same-origin URL. No popup.

Parity sweep (49 strings through both validators): the only mismatches were `httpſ://…` and `HTTPſ://…`.

## Expected

Server and client accept and refuse the same addresses. `httpſ://…` refused on both sides.

## Actual

Server accepts, client refuses; the link is dropped on the next editor save.

## Fix hint

Match the scheme case-insensitively in ASCII only, e.g. an explicit `[hH][tT][tT][pP][sS]?://` (or
`re.IGNORECASE | re.ASCII`; `\S` then means "not ASCII whitespace", which is fine only because the
category check already refuses every C/Z character). Add both strings to the shared parity tests.
