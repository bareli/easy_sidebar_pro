## Problem

A household member who opens the pencil "just to look" and leaves with **סיום / Done** (the
primary, blue, first button, and the natural way out) gets a private copy of the admin's default
layout. Nothing in the normal sidebar changes, so they cannot see that anything happened. From then
on, every change the admin publishes with "קביעה כברירת מחדל לכולם" no longer reaches them. The
only way back is a link ("חזרה לפריסת ברירת המחדל") that appears only inside the editor.

The editor does warn ("זו פריסת ברירת המחדל. שמירה תהפוך אותה לשלכם."), but "Done" does not read
as "save", and the warning is in 12px grey text under the buttons.

## Why it matters

The admin default exists for exactly these users: non-technical family members whom the admin
organises the sidebar for. Opening an editor and pressing Done is the most common exploratory
action. The admin then reorganises, presses "for everyone", and some of the family do not get it.
Neither side can tell why. The breakage is invisible and has no time limit.

## Evidence

![Done with no changes forks the default](https://github.com/bareli/easy_sidebar_pro/blob/main/qa/evidence/UX-001-done-without-changes-forks-default.png?raw=1)

Left: `qa_user` opens the editor; the note says this is the default layout. Middle: after **Done**
with zero changes, the note is gone and "חזרה לפריסת ברירת המחדל" appears (they now own a copy).
Right: after Reset, back on the default.

Websocket `easy_sidebar_pro/subscribe` for `qa_user`:
- before: `{"own":false,"hasDefault":true}`
- after Done with no edits: `{"own":true,"hasDefault":true}`
- after Reset: `{"own":false}`

Source: `actions().done` always calls `save()` (`www/easy-sidebar-pro.js` around line 899); there is
no "unchanged" check.

## Recommendation

1. **Done with no changes = close without saving** (compare the tree and hidden set with what was
   opened). This alone removes almost all accidental forks.
2. When a user on the default does change something, make the consequence explicit at save time,
   once: "Your sidebar will no longer follow the household default. You can go back any time."
3. Optional (owner call): offer "follow the default, plus my changes" later. Not needed for v0.1.

## Kind

`current behaviour is wrong` (an unchanged layout should not change the user's state).
