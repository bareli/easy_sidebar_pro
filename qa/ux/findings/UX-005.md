## Problem

1. **Wording.** HA's Hebrew UI calls the sidebar "סרגל צד" (its own long-press dialog title is
   "עריכת סרגל צד", and `ui.sidebar.edit_sidebar` = "עריכת סרגל צד"). Ours says "עריכת התפריט"
   (edit the menu) for both the pencil tooltip and the editor title. The two editors look like two
   different things, and "תפריט" in HA usually means the ⋮ overflow menus.
2. **Icon-only sidebar.** The pencil is hidden whenever the sidebar is collapsed to icons
   (`:host(:not([expanded])) .esp-edit { display: none }`). A user who keeps the rail collapsed has
   no visible way to the feature; they must know to expand first.
3. **First-run cue.** After install the only change is a grey 20px pencil beside the title, while
   the dashboard toolbar has its own pencil (edit dashboard) on the same screen. Nothing tells the
   user that groups now exist. This is acceptable for v0.1, but the README is the only onboarding.

## Why it matters

Consistency with HA's own wording is what lets a Hebrew user map "this is the sidebar editor, the
better one". Hiding the entry point in a common layout costs discoverability for no gain.

HA's dialog title is in UX-002's screenshot.

## Recommendation

- he `edit`: "עריכת סרגל הצד"; he `editing`: "עריכת סרגל הצד" (or "סידור סרגל הצד"). Keep "סרגל
  הצד" wherever the sidebar is named (`onDefault`, `reset`, `setDefault`: "פריסה" can stay).
- In icon-only mode, show the pencil as a rail item (40px, same column as the icons) or at least
  keep it in the header next to the hamburger.
- Optional first-run: after the integration is added, a one-time pulse on the pencil or a single
  "Organise the sidebar into groups" tooltip. Owner call.
