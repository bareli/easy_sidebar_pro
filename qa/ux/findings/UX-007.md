## Summary

When a save fails, the editor stays open and keeps the changes (good), but the message is not usable:

- Connection lost: `השמירה נכשלה: 3`. The `3` is home-assistant-js-websocket's `ERR_CONNECTION_LOST`
  code; the error is a number, not an object with `message`.
- Server rejection: `השמירה נכשלה: groups['qyfqa9o9']: name contains control characters`. English
  developer text inside a Hebrew sentence, naming an internal group id instead of the group's name.

The message also stays after the connection returns, until the next action.

## Steps to reproduce

1. qa_admin (Hebrew), open the editor, toggle any eye button.
2. Take the browser offline (DevTools Network: Offline), click Done. Wait 3 s.
3. Separately: a server-side rejection, e.g. BUG-014's name.

## Expected

A localized message the user can act on ("No connection to Home Assistant, changes kept, try again";
"Group <name>: ..."). Wording is the owner's call, hence `model:opus`.

## Actual

See above. Reproduced twice for the offline case, twice for the server case.

## Evidence

`err?.message ?? err` in `actions().reset/setDefault/clearDefault` and `Controller.save`; the socket
library rejects with a numeric code.

## Recommended remediation

Map numeric socket codes to a localized "no connection" string; for `invalid_format`, show a localized
generic message (optionally the group's name), not the server text. Keep he/en `STRINGS` in sync.

## Fix prompt

After the owner rules on wording: in `Controller.save` and the `actions()` error paths, show a localized
message for connection errors (numeric `err`) and for `invalid_format`, never the raw server text or a
number. Acceptance: offline Done shows the ruled Hebrew / English text; the editor stays open; Done works
after reconnecting.
