## Summary

Typed input is normalised without telling the user. `192.168.1.251:5000` (a usual Synology address, plain http on the LAN) becomes `https://192.168.1.251:5000`, which gives an SSL error in the new tab. `nas` becomes `/nas`, a Home Assistant page that 404s. The value just changes after Enter with no explanation, so the first test click opens an error page.

## Steps to reproduce

1. Add link, Address `192.168.1.251:5000`, Enter: value becomes `https://192.168.1.251:5000`.
2. Address `nas`, Enter: `/nas`.
3. `config/automation` becomes `/config/automation` (fine); `http://192.168.1.251:5000` opens a new tab (verified); `javascript:alert(1)`, `//evil.com`, `http://`, Hebrew text are refused.

## Expected

A bare host/IP with a port is kept as http, or the user is asked for the scheme; a bare word gets a message ("Start with http:// for a web address or / for a Home Assistant page") instead of a /path.

## Actual

Measured values after Enter: `https://192.168.1.251:5000`, `/nas`. The https rewrite has no screenshot (Evidence unavailable as image: it is a value change).
