## Problem

HA's own Edit sidebar dialog (long-press on the sidebar title) lists pinned panels like any other row,
last in the list (v0.3 writes them last to HA's `panelOrder`). Since v0.2 (UX-002 / #13) an order saved
there is applied to the layout, groups kept. For pinned panels it is not: moving a pinned item to the top
of the list, or reordering the pinned items among themselves, and pressing Save changes nothing in the
sidebar. No message says why. HA's own data now holds the new order, so the next time the dialog opens it
shows an order the sidebar does not follow.

What still works in the same dialog: hiding a pinned panel removes it from the grid and showing it again
brings it back; reordering top-level rows is adopted with groups and pins kept.

## Why it matters

This is the same "my change in HA's dialog was silently dropped" experience UX-002 fixed for groups; the
pinned grid reintroduces it for a new kind of row. Users who know HA's dialog (or follow HA docs) will
try it there first.

## Evidence

Steps: layout `order [g:a, map, energy, logbook]`, `grid [todo, calendar, media-browser]`, HA
`panelOrder` matching (pins last). Open HA's dialog, drag "Media" (pinned) to the top, Save.

| | Before | After Save |
|---|---|---|
| HA `panelOrder` | ..., todo, calendar, media-browser | **media-browser**, dash-kids, ..., todo, calendar |
| Stored layout `grid` | todo, calendar, media-browser | todo, calendar, media-browser (unchanged) |
| Sidebar pins | todo, calendar, media-browser | todo, calendar, media-browser (unchanged) |

Also reproduced: reordering only within the pins (media-browser before todo) and moving todo to the top;
both ignored. Hiding / showing a pinned panel and moving `logbook` to the top were adopted correctly.
(The dialog was driven through its own `value-changed` event and `_save()`, the same path its drag
handles use.)

The sidebar after Save: Media is still the last pinned icon of the bottom grid (leftmost in RTL), not at the top:

The images are committed on `main` but were not pushed when this was filed; Evidence unavailable: not
pushed yet. They render once `main` is pushed.

Code: `L.adoptOrder()` (`www/layout.js`) re-sorts `order` and each group's `panels` by HA's ranks and
copies `grid` through untouched; SPEC §7.3 says only that "HA's native `panelOrder` lists pinned panels
last" and is silent on adopting changes to them.

## Recommendation

Owner decision on what HA's dialog may do to pins:

1. Pins follow HA's relative order among themselves (as group members do), and stay pinned whatever their
   position in HA's list. Smallest change, consistent with groups.
2. As 1, and moving a pinned panel above the non-pinned rows in HA's dialog unpins it.
3. Pins are editor-only: keep ignoring HA's dialog for them, but say so (for example HA's toast, as the
   UX-002 fork note does).

## Kind

current behaviour is wrong (silent no-op); the right behaviour is a product call.

## Prototype

Not offered.

## Fix handback (2026-10-01, commit 5b48d95)


Fix (`www/layout.js` `adoptOrder`): the layout's `grid` is re-sorted by HA's ranks with the same slot rule as group members. Pinned panels stay pinned wherever HA lists them; a pin HA does not list keeps its slot; v0.2 layouts without `grid` stay without one.
