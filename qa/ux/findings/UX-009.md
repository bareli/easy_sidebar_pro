## Problem

With the new button on, the header has two buttons and the title gets 117 px for 143 px of text, so it
is truncated (expected: SPEC §7.2 says the button "shortens the title", which is why it is off by
default). In English it reads "Home Assi...", which is fine. In Hebrew the default instance name "Home
Assistant" is Latin text in a right-to-left header, and the new `text-overflow: ellipsis` cuts it at the
paragraph's end, which is the left edge: the user sees "...e Assistant", with the beginning of the name
missing. At 320 px it is "...me Assistant".

## Why it matters

The owner's primary locale is Hebrew and most Israeli installs keep the English instance name. The title
is on every page; a name with its first letters missing reads as broken, not as shortened.

## Evidence

Measured: `.menu .title` width 117 px, `scrollWidth` 143 px, `direction: rtl` (Hebrew) / `ltr` (English),
text "Home Assistant" in both.

Hebrew:

![English title cut at its end](https://github.com/bareli/easy_sidebar_pro/blob/main/qa/evidence/v030-qa-UX-009-title-en.png?raw=1)

The images are committed on `main` but were not pushed when this was filed; Evidence unavailable: not
pushed yet. They render once `main` is pushed.

Code: v0.3 adds `.menu .title { overflow: hidden; text-overflow: ellipsis; }` to `SIDEBAR_CSS` in
`www/easy-sidebar-pro.js`.

## Recommendation

Let the title's own text set the truncation side: `unicode-bidi: plaintext` on `.menu .title` (or
`dir="auto"` on the element), so a Latin name in a Hebrew UI shows "Home Assi..." and a Hebrew name
still truncates at its own end. Acceptance: Hebrew UI, title "Home Assistant", button on: the visible
text starts with "Home"; a long Hebrew title truncates on its left.

## Kind

current behaviour is wrong (for a Latin name in a Hebrew UI).
