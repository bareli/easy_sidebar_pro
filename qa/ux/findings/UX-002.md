## Problem

Once a user has saved a layout, two editors exist for the same sidebar:

- The **pencil** (ours): groups, order, hide.
- HA's **long-press dialog**: a flat list with drag handles, eye buttons, a Save button, and the
  subtitle "מסונכרן בכל המכשירים" (synced across devices). It knows nothing about groups.

Hiding in HA's dialog works (shared list). **Reordering does not.** It saves without error, but the
sidebar keeps our stored order, so the user's drag in a native HA dialog appears to do nothing.

## Why it matters

Experienced HA users reach for long-press first; it is HA's documented way to reorder. A dialog that
accepts the change, says "saved", and has no effect is the kind of failure that makes people
uninstall a plugin. Family members who were taught long-press years ago will hit it too.

## Evidence

![HA's native dialog shows a flat list beside the grouped sidebar](https://github.com/bareli/easy_sidebar_pro/blob/main/qa/evidence/UX-002-native-dialog-flat-list.png?raw=1)

Reproduction (the write HA's dialog makes on Save): with a saved layout, set `frontend/set_user_data`
`sidebar.panelOrder` to put `dash-garden` first, then reload. The first rows stay `home, dash-kids,
[group], map...` and Garden does not move. The original user data was restored afterwards.

## Recommendation

An owner decision (SPEC §6 keeps long-press on HA's dialog). Options, from least to most work:

1. Accept HA's order where it does not conflict with groups: when HA's `panelOrder` changes outside
   our editor, re-sort the top-level panels and each group's members by it (groups stay where they
   are). Reorder in the native dialog then "mostly works".
2. Long-press opens our editor instead, or our editor shows a line "Use the pencil to reorder; HA's
   Edit sidebar only hides panels while groups are on."
3. At minimum: a README line about which dialog does what.

## Kind

`current behaviour is wrong` (a visible editor saves silently with no effect).

Not applicable.

## Related observation (functional review)

"Reset to the default layout" does not rewrite HA's native `panelOrder`, so the forked order stays in HA's user data and HA's dialog keeps showing it.
