Standard: WCAG 2.1 SC 2.4.3 Focus Order (Level A). In the editor, pressing Enter in a group name field
calls `blur()`, and the rename re-renders the editor. Focus ends on `<body>`; the next Tab starts again at
"Done" at the top of the editor, not at the next control after the name. With 20-40 panels that is
roughly 40 Tab presses to get back to where the user was. A screen reader user hears nothing meaningful
(focus is on the document).

## Steps to reproduce

1. Open the editor (mouse click on the pencil; see BUG-003 for the keyboard path).
2. Focus "הוספת קבוצה" (Add group), press Enter. Focus moves to the new name field (good).
3. Type "בית", press Enter.
4. Read the active element: `BODY`.
5. Press Tab: focus goes to `button.btn.primary` (Done), the first control of the editor.

## Expected

After committing a name, focus stays on the name field (or moves to a defined next control). Not lost.
Expectation from WCAG 2.4.3; the code itself already restores focus elsewhere via `data-focus-key`.

## Actual

`onkeydown` in `groupBlock` runs `e.target.blur()`; the `change` handler then calls `actions.rename`,
which calls `set(...)` with no focus key, and `render()` replaces the DOM. Active element is `BODY`.

## Evidence

Playwright log: `Enter name -> focus: body`, then `Tab after blur -> esp-editor > button.btn.primary`.

## Screenshots

Not a visual defect (focus position). Evidence is the log above.

## Likely root cause

Likely: `blur()` is used to fire `change`; `rename` passes no focus key to `ed().set(...)` so nothing
restores focus. Fix by passing `` `name:${id}` `` as the focus key (as the invalid-name path already does).

## Relevant files

`www/easy-sidebar-pro.js`: `EspEditor.groupBlock` (`onkeydown`), `actions().rename`.

## Recommended remediation

On Enter commit the rename and keep focus on the name input (`ed().set({tree, error: ""}, \`name:${id}\`)`).
Verify: after Enter, `document.activeElement` path ends at `input.name-input`; Tab moves to the ungroup button.

## Regression test

`A11Y-02`: focus after Enter in the name field. Browser-level; a unit test cannot see focus.
