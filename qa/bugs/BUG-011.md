## Summary

While dragging, if the pointer leaves the list sideways (for example over the dashboard), the drop
indicator disappears, which reads as "dropping here does nothing". Releasing there still moves the row
to the last place that was highlighted. A user who drags out of the sidebar to abort gets a move they
did not ask for.

## Steps to reproduce

1. qa_admin, desktop, open the editor.
2. Drag the handle of מפה (`p:map`) until the line shows above חדר ילדים (`p:dash-kids`).
3. At the same height, move the pointer left over the dashboard (x = 600-700). The line disappears.
4. Release.

## Expected

Plan DND-08: "drop outside the list does nothing harmful". With no indicator visible, the release should
not move anything; the editor's own `_dragEnd` already skips the drop when there is no target.

## Actual

`p:map` moves before `p:dash-kids`. Reproduced twice (once with `p:home`, once with `p:map`). Releasing
in the list's own column (x = 1300) behaves correctly because a row is under the pointer there.

## Evidence

```

marks over dashboard     0
```

## Screenshots

![Pointer over the dashboard, no indicator shown; release still moves the row](https://github.com/bareli/easy_sidebar_pro/blob/main/qa/evidence/BUG-011-release-over-dashboard-no-indicator.png?raw=1)

## Likely root cause

From `_updateTarget`: it clears the marks first, then, when no row is under the pointer and the pointer's
y is within the rows' vertical range, it returns without resetting `d.target`. The previous target
survives and `_dragEnd` drops on it. Proof: setting `d.target = null` on that path makes the release a
no-op.

## Relevant files

- `custom_components/easy_sidebar_pro/www/easy-sidebar-pro.js`: `EspEditor._updateTarget`, `_dragEnd`.

## Recommended remediation

Set `d.target = null` whenever `_updateTarget` exits without marking a row, so what is shown is what
happens. Consider treating a pointer outside the editor's horizontal bounds as "no target" even above or
below the list.

## Fix prompt

In `EspEditor._updateTarget`, reset `this._drag.target` to null on every early return that leaves no
drop mark. Acceptance: hovering a row, moving the pointer horizontally out of the sidebar and releasing
leaves the tree unchanged; drops on rows and above / below the list still work (DND-01..05, DND-07).

## Regression test

DND-08 (Playwright: hover a target, move out sideways, release, tree unchanged).
