## Summary

Standard: WCAG 2.1 SC 3.3.1 Error Identification (A), 1.3.1 Info and Relationships (A), 4.1.3 Status
Messages (AA). Clearing a group name and pressing Enter shows "צריך שם לקבוצה" in a banner at the top of
the editor (above "Add group"), possibly a screen-height away from the field. The field has no
`aria-describedby` and no `aria-invalid` (the editor re-renders and the attribute set on the old node is
lost), and the field silently reverts to the previous name, so it looks valid while an error is shown
elsewhere. The icon field in the same editor does this correctly (`aria-describedby` + `aria-invalid`).

## Steps to reproduce

1. Open the editor (mouse click on the pencil), create a group named "בית".
2. Focus the name field, Ctrl+A, Delete, Enter.
3. Inspect: the field is `<input class="name-input" aria-label="שם הקבוצה" ...>` with no `aria-invalid`,
   no `aria-describedby`; value is back to "בית"; the error `<div class="error" role="alert">` is in `.bar`.

## Expected

The error text is programmatically associated with the field (`aria-describedby`), the field is
`aria-invalid="true"`, and the message is announced when it appears.

## Actual

As above. Announcement relies on a freshly inserted `role="alert"` node. No screen reader was available, so
how it is spoken is **not verified**. The missing association and the missing invalid state are verified in the
DOM and in the Chrome accessibility tree.

## Evidence

```
error html: <div class="error" role="alert">צריך שם לקבוצה</div>
name input: <input class="name-input" type="text" maxlength="50" aria-label="שם הקבוצה" data-focus-key="name:...">
```

## Likely root cause

Likely: `actions().rename` sets `aria-invalid` on the input and then `ed().set({error})` re-renders the whole
editor, discarding it. The error is a single editor-level string rendered in `.bar`.

## Relevant files

`custom_components/easy_sidebar_pro/www/easy-sidebar-pro.js`: `actions().rename`, `EspEditor.render` (error in `.bar`), `groupBlock`.

## Recommended remediation

Render a per-field error element next to the group name with an id; set `aria-describedby` and
`aria-invalid="true"` on the input in the next render; make clear whether the old name was kept.
Verify: the field exposes invalid and a description in the AX tree; the error sits next to the field.

## Regression test

A11Y-03. The markup (aria-invalid, aria-describedby after an invalid rename) is unit-testable; the announcement is not.
