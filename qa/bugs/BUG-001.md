## Summary

The editor's top bar (title, **Done**, **Cancel**, hints) is meant to stay pinned (`.bar { position:
sticky; top: 0 }`), but it scrolls away with the list. On a phone, or with the 10-40 panels typical
users have, Done and Cancel leave the screen as soon as the user scrolls to the row they want to
move. They then have to scroll all the way back up to finish. On a 320x568 phone the edit area is
already small: the bar takes about 140px, and HA's settings, notifications and profile block below
takes about 150px, which leaves roughly four editable rows on screen.

## Steps to reproduce

1. 320x568, touch, Hebrew, `qa_admin`. Open the drawer (menu button), tap the pencil.
2. Scroll the panel list down.

## Expected

The Done / Cancel bar stays at the top of the list while scrolling. Source of expectation: the CSS
intent in `EDITOR_CSS` (`.bar { position: sticky; top: 0; z-index: 2 }`).

## Actual

The bar scrolls off: its top moved from 64px to -308px after one wheel step of 400px.

## Evidence

Bar top measured via `getBoundingClientRect()`: 64 → -308 after scrolling. Scroll chain under the
editor (from the editor upward):

```
esp-editor               overflow=visible       h=720
div.base ha-scrollbar    overflow=hidden auto   h=720  scrollHeight=720   <- scroll container that never scrolls
ha-list-nav.before-spacer overflow=hidden auto  h=348  scrollHeight=720   <- the element that actually scrolls
```

## Screenshots

![Bar at the top, then gone after scrolling, 320x568](https://github.com/bareli/easy_sidebar_pro/blob/main/qa/evidence/BUG-001-done-cancel-scroll-away-320.png?raw=1)

## Likely root cause

Likely: HA's `ha-list-nav` has an inner `div.base` with `overflow: hidden auto`. That makes it the
sticky bar's nearest scroll container, but it is as tall as its content and never scrolls (the outer
`ha-list-nav` scrolls). Sticky is measured against a container that never moves, so it never sticks.
What would prove it: give `div.base` `overflow: visible` in devtools and see the bar stick.

## Relevant files

- `custom_components/easy_sidebar_pro/www/easy-sidebar-pro.js` - `EDITOR_CSS` `.bar`, `EspEditor.render()`

## Recommended remediation

Make the bar stick for real. One option is to keep it outside the scrolled list. Another is a
compact one-line bar (title dropped; Done and Cancel on one row; hint collapsible after the first
use), so the phone keeps more editable rows. Acceptance: at 320x568 and at 1440x620, after scrolling
the editor to its end, Done and Cancel are visible and tappable without scrolling back.
