## Summary

Every Done in the editor rewrites HA's own `sidebar.hiddenPanels` and `sidebar.panelOrder` using only the
panels HA lists at that moment. Entries for panels that are temporarily absent (an add-on that is
stopped, an integration panel that failed to load) are deleted. When that add-on starts again, the panel
the user had hidden reappears in the sidebar, and its native order is lost. The product deliberately keeps
missing panels' places in its own layout (PROJECT.md *Deliberate behaviour*), but the hidden state lives
only in HA's list (SPEC §2.5, "one source of truth"), so this is where it gets lost.

## Steps to reproduce

1. As qa_admin, set HA's sidebar data so it includes a panel HA does not list now:
   `frontend/set_user_data key=sidebar value={"panelOrder":[..., "hassio-stopped"], "hiddenPanels":["media-browser","hassio-stopped"]}`.
2. Open the editor, change nothing (or anything), click Done.
3. `frontend/get_user_data key=sidebar`.

## Expected

`hiddenPanels` still contains `hassio-stopped` (the user's hidden choice for a panel the editor never
showed). Inference from SPEC §2.5 and from the deliberate rule that a missing panel keeps its place; not
checked whether HA's own Edit sidebar dialog preserves such entries.

## Actual

```
before: {"panelOrder":[...,"media-browser","hassio-stopped"],"hiddenPanels":["media-browser","hassio-stopped"]}
after:  {"panelOrder":["home","todo","calendar","gd-qa","map","good-days","media-browser","dash-kids","dash-cameras","dash-energy-home"],
         "hiddenPanels":["media-browser"]}
```

Reproduced twice (`ghost-addon` in run 1, `hassio-stopped` in run 2).

## Likely root cause

`Controller.save()` filters both lists through `known = new Set(this.edit.paths)` (panels HA lists now):
`panelOrder = flatten(tree).filter(p => known.has(p) ...)` and
`hiddenPanels = [...hidden].filter(p => known.has(p) ...)`; `hidden` is built from `_hiddenPanels` but
only for panels in `all`.

## Relevant files

- `custom_components/easy_sidebar_pro/www/easy-sidebar-pro.js`: `Controller.save`, `Controller.allPanels`.

## Recommended remediation

Carry over entries of `current.hiddenPanels` (and `current.panelOrder`) whose panel is not in `known`.

## Fix prompt

In `Controller.save`, keep every entry of the existing `current.hiddenPanels` whose path is not among the
panels the editor knows, and append existing `current.panelOrder` entries not among them to the end of the
new `panelOrder`. Acceptance: with `hiddenPanels` containing a path HA does not list, a Done from the
editor leaves that path in `hiddenPanels` and in `panelOrder`; known panels behave as today.
