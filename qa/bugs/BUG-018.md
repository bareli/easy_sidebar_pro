**WCAG 2.1 AA: 2.5.3 Label in Name** (level A).

## Summary

The group's options button shows the text "עוד" (More) and its accessible name is "אפשרויות נוספות עבור {group}". In Hebrew the visible word is not contained in the name, so a speech-input user saying "לחץ על עוד" does not activate it, and the spoken and visible names differ. English passes ("More" is inside "More options for X"). Neighbouring group buttons ("פירוק" in "פירוק הקבוצה X", "לשוניות" in "לשוניות, X") pass.

## Steps to reproduce

1. 8173 (Hebrew), open the editor, read the AX tree of the group header buttons.

## Expected

The accessible name contains the visible label (WCAG 2.5.3).

## Actual

AX: `button "אפשרויות נוספות עבור בית 🏠 Home" expanded=false` with visible text `עוד`.

## Evidence

CDP `Accessibility.getFullAXTree`, `~/.claude/qa-playwright/espjs/a11y-2.mjs`. Strings (he): `optMore: "עוד"`, `options: "אפשרויות נוספות עבור {name}"`.

## Screenshots

![group row buttons incl. עוד (320 px)](https://github.com/bareli/easy_sidebar_pro/blob/main/qa/evidence/BUG-018-group-more-he.png?raw=1)

## Likely root cause

Likely: the group button reuses the row-level `options` string as its aria-label.

## Relevant files

- `custom_components/easy_sidebar_pro/www/easy-sidebar-pro.js` (group `.opt.more`, strings `optMore`, `options`)

## Recommended remediation

Make the Hebrew name contain the visible word (for example "עוד: אפשרויות נוספות עבור {name}") or change the visible label to "אפשרויות נוספות".
