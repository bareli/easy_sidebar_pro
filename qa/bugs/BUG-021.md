## Summary

For a group name, an invalid value blocks Done: the field is focused and the message repeats (EDIT-13,
BUG-005). The v0.5 fields behave differently. When a link's name or address, or an entry's badge /
show-only-when entity, is invalid, the field shows its error but Done closes the editor anyway and saves
the previous value. The user typed something, saw a red message, pressed Done, and the editor closed as if it
worked; what they typed is gone without a word. In addition, the error under an empty **link** name says
"צריך שם לקבוצה" / "Enter a group name".

## Steps to reproduce

1. Layout with a link `Keep` (`/config`) and `history` with badge `sensor.good`.
2. Pencil -> ⋮ on Keep. Clear the Name field, Enter: error "צריך שם לקבוצה".
3. Address `javascript:alert(1)`, Enter: error "יש להזין נתיב שמתחיל ב-/ ...".
4. ⋮ on History, badge `Sensor Bad`, Enter: error "יש להזין מזהה ישות ...".
5. Click Done.

## Expected

Done behaves as for a group name (SPEC 9.1: "Done refuses a link without a valid address (focus +
message)"; EDIT-13 rule for invalid names): it stays open, focuses the first field in error and repeats
its message. The empty link name says a link name is needed. (The exact rule for option fields is my
inference from the group-name behaviour; the owner may prefer "Done keeps the old value and says so".)

## Actual

Editor closes on the first click. Stored afterwards: link `{"name": "Keep", "url": "/config"}`, history
`{"badge": "sensor.good"}` - all three typed values discarded silently. Reproduced twice (eng-v3.mjs on a new
link: name cleared -> saved as "קישור חדש", badge "Sensor Open" -> saved as null; eng-b2.mjs as above).

## Evidence

eng-b2.mjs output: `name: {v: "", invalid: "true", err: "צריך שם לקבוצה"}`, `url: {invalid: "true"}`,
`badge: {invalid: "true"}`, `editorOpenAfterDone: 0`, stored `link: {name: "Keep", url: "/config"}`,
`history: {badge: "sensor.good"}`.

## Screenshots

![link options with name and address errors, just before Done](https://github.com/bareli/easy_sidebar_pro/blob/main/qa/evidence/BUG-021-field-errors-before-done.png?raw=1)

## Likely root cause

`actions.done` only consults `focusInvalidName()` (group names in `nameErrors`) and `focusInvalidLink()`
(which checks the stored `meta.links`, where a rejected edit never landed, so the old valid value passes).
`setLink` / `setItem` return an error text and leave the old value, without recording that the field is
pending invalid. `setLink("name")` uses the `nameRequired` string (group wording).

## Relevant files

- `custom_components/easy_sidebar_pro/www/easy-sidebar-pro.js` (`actions.done`, `setLink`, `setItem`,
  `focusInvalidLink`, `optField`, STRINGS `nameRequired`)

## Recommended remediation

Track invalid option fields like `nameErrors` (key = focus key), make `done` / `setDefault` refuse while any
is pending (open that row's options, focus the field, repeat the message), clear on a valid commit or on
Cancel. Add a `linkNameRequired` string (he/en).
