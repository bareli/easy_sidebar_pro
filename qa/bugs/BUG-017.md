**WCAG 2.1 AA: 1.4.11 Non-text Contrast.** Same class as closed BUG-007 (group name input).

## Summary

The inputs inside the new ⋮ options block (link name, address, icon, badge entity, show-when entity, search words) use `border: 1px solid var(--divider-color)`: `rgba(0,0,0,.12)` = 1.31:1 on white in light, `rgba(225,225,225,.12)` = 1.38:1 on 28,28,28 in dark. The field fill (white) against the options panel (229,229,229) is 1.27:1. A low-vision user cannot see where the fields are.

## Steps to reproduce

1. 8173, open the editor (Enter on the pencil), Enter on ⋮ of any row.
2. Read `getComputedStyle(input).borderTopColor` for `.row-opts input`.

## Expected

A visible 3:1 boundary or equivalent affordance (BUG-007's acceptance; WCAG 1.4.11).

## Actual

Border 1.31:1 (light), 1.38:1 (dark). The "Move to" select is a browser control with its own border and is not part of this.

## Evidence

`~/.claude/qa-playwright/espjs/a11y-10.mjs`: `inputBorder: {c:"rgba(0, 0, 0, 0.12)", vsParent:1.31}`; dark 1.38.

## Screenshots

![options block open, 320 px, light](https://github.com/bareli/easy_sidebar_pro/blob/main/qa/evidence/BUG-017-options-fields-narrow-light.png?raw=1)

## Likely root cause

Likely: CSS `.row-opts .field input` (line ~699) reuses the decorative `--divider-color`. Proof: use a 3:1 colour and re-measure.

## Relevant files

- `custom_components/easy_sidebar_pro/www/easy-sidebar-pro.js` EDITOR_CSS `.row-opts .field input`

## Recommended remediation

A border colour with at least 3:1 against the options panel in both themes (for example a mix of `--secondary-text-color`), keeping the invalid and focus states.
