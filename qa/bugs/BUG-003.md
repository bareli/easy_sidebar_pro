Standard: WCAG 2.1 SC 2.1.1 Keyboard (Level A). The pencil button that opens the editor takes focus by
Tab and has a name, but Enter and Space do nothing. Mouse click opens the editor. A keyboard-only user
cannot reach the editor at all, so every keyboard feature behind it (Alt+Arrow move, rename, icon, hide)
is unreachable. This outranks every other finding in this review.

## Steps to reproduce

1. Log in as `qa_admin` (Hebrew), desktop viewport 1280x900, sidebar expanded.
2. Press Tab twice from page start: focus is on `button.esp-edit` ("עריכת התפריט").
3. Press Enter. Nothing happens; focus stays on the pencil, no `esp-editor` in the sidebar.
4. Press Space. Same.
5. Click the pencil with the mouse: editor opens, focus moves to "סיום" (Done).

## Expected

Enter and Space activate a `<button>` (WCAG 2.1.1; native button behaviour).

## Actual

Both keys are `defaultPrevented` before the browser can synthesise the click, so no `click` event fires.

## Evidence

Capture-phase listeners on the document plus bubble-phase listeners along the pencil's composed path,
after pressing Enter with the pencil focused:

```
button.esp-edit   keydown Enter defaultPrevented=false
div.menu          keydown Enter defaultPrevented=true     <- first element that prevents it
ha-sidebar, slot, div.sidebar-shell, div.layout, ha-drawer, ... all true after that
```

Space behaves identically (`defaultPrevented=true`, no click). A `click` listener on the button logs only for the mouse case.
Tested with Chromium (Playwright), keyboard events from `page.keyboard`; no screen reader. A real user's
Enter/Space go through the same keydown path, so the result is expected to match.

## Screenshots

Not a visual defect (behavioural). Evidence is the event trace above.

## Likely root cause

Likely: HA's `.menu` container has a keydown handler for Enter/Space (the title/toggle) that calls
`preventDefault()` on events bubbling from any child. The button is appended inside `.menu` in
`Controller.afterUpdate` (`www/easy-sidebar-pro.js`, `menu.append(btn)`) and only stops pointer/touch/mouse
events, not `keydown`. To prove: add `btn.addEventListener("keydown", e => e.stopPropagation())`.

## Relevant files

`custom_components/easy_sidebar_pro/www/easy-sidebar-pro.js` (Controller.afterUpdate, pencil button).

## Recommended remediation

Add `keydown` (and `keyup`) to the list of event types stopped at the button, next to `pointerdown` etc.
Re-run the sequence above: Enter and Space must each open the editor, focus must land on Done. Also check
the English LTR sidebar and the narrow-drawer sidebar (640 and 320 px).

## Regression test

`A11Y-01`: keyboard Enter and Space on the pencil open the editor. A unit test can only pin that the
button stops `keydown` propagation; the browser sequence is the real evidence (a markup test cannot see
HA's `.menu` handler).
