## Summary

The 50-character name limit is counted differently on the two sides. The server (`len()` in Python) counts
code points, so it stores names of up to 50 emoji / astral characters (100 UTF-16 units). The editor
(`maxlength`, `String.slice(0, 50)` in `cleanName`) counts UTF-16 units. When such a stored name is edited,
`cleanName` cuts it at unit 50; if the cut falls inside a surrogate pair the name ends in a lone surrogate.
`JSON.stringify` sends it as `\ud83d`, HA's websocket JSON parser rejects the frame and **closes the
browser's whole websocket connection** ("Disconnected: Received invalid JSON"). The editor shows the
generic "לא ניתן לשמור. נסו שוב." with no reason, the name field shows a broken character, and every retry
disconnects again. When the cut is on a pair boundary the name is silently shortened instead (stored
`ab` + 26 emoji became `ab` + 24 emoji after an unrelated edit of the field).

Nothing reaches storage (HA refuses the frame before our handler), so storage is not corrupted.

## Steps to reproduce

1. As any user, over WS: `easy_sidebar_pro/save` with a group named `"ab" + "😀"×26` (28 code points,
   54 UTF-16 units). Server: `success: true`, stored as is.
2. Open the editor (pencil). The name field shows the full 54-unit value (`maxlength` does not cut a
   programmatic value).
3. Delete the `b` (select position 1-2, Delete), press Enter. The field now shows `a` + 24 emoji + `�`.
4. Click Done.

Same for a link name (`setLink` uses `cleanName`) and for search words (`cleanAliases` slices at 100
units; the server counts 100 code points).

## Expected

One length rule on both sides (SPEC: "Keep server and client rules identical", historical risk area
*Validation parity*). A name the server accepts is editable without loss, and the editor never produces a
string that cannot be encoded. Either the server counts UTF-16 units like the browser, or the editor
counts code points and never cuts inside a pair (`Array.from(name).slice(0, 50).join("")`).

## Actual

- WS probe (python, raw frames): names of 25, 26, 50 emoji -> `success`; 51 emoji -> `name must be
  1-50 characters`; any lone surrogate (`"abc\ud83d"`, `"abc\ude00"`) -> connection closed (code 1000),
  no result message.
- Node, `cleanName("a".repeat(49) + "😀")` and `cleanName("a" + "😀".repeat(26))` both return a
  50-unit string ending in a lone high surrogate.
- Browser: after Done, `hass.connection` fired `disconnected` then `ready` 8 ms later; editor stays
  open with "לא ניתן לשמור. נסו שוב."; storage unchanged (still the 28-code-point name).
- Typing / pasting in the browser is safe: Chrome's `maxlength` never splits a pair (49 `a` + emoji
  insert / paste -> refused; 30 emoji pasted -> 25 kept).

## Likely root cause

Proven by the probes above: `layout.py _name` uses `len(name)` (code points); `layout.js cleanName`
uses `.slice(0, MAX_NAME)` (UTF-16 units) and the inputs use `maxlength` (UTF-16 units). Same pair for
`_aliases` / `cleanAliases` (`MAX_ALIASES`) and `_url` / `validUrl` (`MAX_URL`; a stored address with
astral characters over 2000 units makes `focusInvalidLink` block Done for a link the server accepted).

## Relevant files

- `custom_components/easy_sidebar_pro/layout.py` (`_name`, `_aliases`, `_url`)
- `custom_components/easy_sidebar_pro/www/layout.js` (`cleanName`, `cleanAliases`, `validUrl`)
- `custom_components/easy_sidebar_pro/www/easy-sidebar-pro.js` (name / link / alias inputs, `maxlength`)

## Recommended remediation

Pick UTF-16 units as the one unit (it is what `maxlength` enforces): server `len(name.encode("utf-16-le")) // 2`
for names, aliases and URLs; client slices by code point so it can never leave a lone surrogate; server
refuses `Cs` explicitly. Add parity cases to `tests_js/` and `tests/test_layout.py`: 25 / 26 emoji, 49 `a` +
emoji, lone surrogates.
