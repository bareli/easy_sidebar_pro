## Summary

A text input keeps a pasted tab (it turns pasted newlines into spaces). The editor's cleaning removes every
control character (`\p{Cc}`) with `""` before anything else, and a tab is a control character, so the words
on both sides are joined: pasting `Living<TAB>Room סלון` (two cells copied from a spreadsheet) gives the
group name `LivingRoom סלון`; search words `מילה   word<TAB>תג` are stored as `מילה wordתג`. The server
would refuse the tab, so the editor cleaning it is right; only the replacement is wrong.

## Steps to reproduce

1. Pencil, focus a group name, paste `Living\tRoom סלון` (clipboard), Enter.
2. ⋮ on any row, Search words: type / paste `מילה   word\tתג`, Enter, Done.

## Expected

Whitespace control characters (tab, and the C1 NEL / `\x1c-\x1f` separators) become a space, then spaces
are trimmed / collapsed: `Living Room סלון`, `מילה word תג`. (Inference: a tab separates words; the plan
EDIT-23 asks for "cleaned", not merged.)

## Actual

Field after Enter: `LivingRoom סלון`. Stored aliases: `"מילה wordתג"`. Node: `cleanName("Living\tRoom")` ->
`"LivingRoom"`, `cleanAliases("a\tb c")` -> `"ab c"`.

## Evidence

eng-b3.mjs: `pasted: "Living\tRoom סלון"`, `afterEnter: "LivingRoom סלון"`; eng-v3.mjs stored
`items["l:…"].aliases = "מילה wordתג"`.

## Screenshots

![pasted Living<TAB>Room shows as LivingRoom](https://github.com/bareli/easy_sidebar_pro/blob/main/qa/evidence/BUG-023-tab-glued-name.png?raw=1)

## Likely root cause

`cleanName` and `cleanAliases` in `www/layout.js` run `.replace(/[\p{Cc}\p{Cf}]/gu, ...)` returning `""` for
every Cc, before `.trim()` / `.split(/\s+/)`.

## Relevant files

- `custom_components/easy_sidebar_pro/www/layout.js` (`cleanName`, `cleanAliases`)

## Recommended remediation

Replace `\s` control characters with a space first (`.replace(/[\t\n\v\f\r\x1c-\x1f\x85]/g, " ")`), then drop
the remaining Cc / Cf. Node cases in `tests_js/`.
