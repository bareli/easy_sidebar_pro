## Summary

Standard: WCAG 2.1 SC 1.3.1 Info and Relationships (A) (ARIA required owned elements). Measured in the DOM:

- Normal sidebar: HA's panels are `role="listitem"`; the `esp-group` header is `role="button"` among them
  (siblings: `ESP-GROUP:button, HA-LIST-ITEM-BUTTON:listitem, ...`). A list's item count and position
  exclude groups; children are siblings of the header, not nested. The collapse state on the header (`aria-expanded`) is fine.
- Editor: `<div class="list" role="list">` directly contains the "Add group" `<button>`;
  `<div class="children" role="list">` directly contains `<div class="empty">` ("גררו לכאן פריטים"). A list may own only list items.

How this is spoken depends on the screen reader and **was not verified** (none available). Low severity: names, roles and states are right.

## Steps to reproduce

1. Inspect the DOM of the sidebar and of the open editor, or run an ARIA structure check.

## Expected

List containers own only list items: wrap the add button and the empty hint in `role="listitem"` or move them out of the list.
Decide the group header role (a listitem wrapping a button, or a documented deviation).

## Actual

See Summary.

## Evidence

`nav role=null parent=SLOT siblingRoles=ESP-GROUP:button,HA-LIST-ITEM-BUTTON:listitem,...`; the editor's
outerHTML shows `<div class="list" role="list"><button class="add" ...>`.

## Screenshots

Not a visual defect.

## Likely root cause

Likely: roles added to name the editor list (`aria-labelledby`) without wrapping the extra children.

## Relevant files

`custom_components/easy_sidebar_pro/www/easy-sidebar-pro.js`: `EspEditor.render`, `groupBlock`, `EspGroup.connectedCallback`.

## Recommended remediation

Move the add button above the list, wrap `.empty` in a listitem, decide the group header role. Re-run the structure check.

## Regression test

A11Y-06. A markup test is valid here: the structure is in the markup.
