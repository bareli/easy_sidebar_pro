## Summary

After typing in a group name field, the next click on any editor button does nothing. The most common
path, "add group, type a name, click Done", leaves the editor open with no message; the user has to
click Done a second time. Same for Cancel, the hide/show eye and Add group. No data is lost, but Done
looks broken on the most common editing path.

## Steps to reproduce

1. qa_admin, desktop. Click the pencil next to the sidebar title.
2. Click into a group's name field and type any text. Do not press Enter or Tab.
3. Click **Done** (סיום) once.

## Expected

The editor saves and closes on that click (plan EDIT-07: "Done saves"). Nothing in SPEC or code comments
makes an ignored click intentional.

## Actual

The editor stays open; the typed name is applied to the field. A second click on Done saves and closes.
Reproduced 3 times on Done. Same pattern for Cancel (first click ignored), the eye button on `p:map`
(first click ignored, second hides) and Add group (no group added on the first click).

## Likely root cause

Strongly indicated by the code path and by the symptom being identical for every button: the name input
renames on `change` (fires on blur). Pressing the mouse on a button blurs the input, `actions.rename`
calls `ed().set(...)`, and `EspEditor.render()` rebuilds the whole shadow content with `replaceChildren`.
The button that received `mousedown` is detached before `mouseup`, so the browser dispatches no `click`
on it. Same mechanism as BUG-004 (focus lost after Enter), different symptom. Proof: a build where a
valid rename does not re-render makes the single click work.

## Relevant files

- `custom_components/easy_sidebar_pro/www/easy-sidebar-pro.js`: `groupBlock` (`onchange` rename),
  `actions().rename`, `EspEditor.render` (`replaceChildren`).

## Recommended remediation

Do not rebuild the DOM as a side effect of the name field losing focus: update `this.tree` on a valid
rename without re-rendering (the input already shows the value), and re-render only for the error case;
or commit pending input values at the start of every action.

## Fix prompt

In `www/easy-sidebar-pro.js`, make a valid rename triggered by the name field's `change` event update the
editor tree without replacing the editor's buttons, so the click that caused the blur still lands.
Acceptance: after typing a name and clicking Done once, the editor closes and the stored group name
equals the typed text; a single click also works for Cancel, the eye button and Add group right after
typing. Keep the empty-name error. No `innerHTML`, no `console.log`. Coordinate with BUG-004 (same code).
